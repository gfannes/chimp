- [x] Create a format to represent a filesystem in a single file. This format must be easy to read with a text editor. The goal is to use such filesystem-in-single-file to create different tests: an input file to describe a few groves, a chimp command and reference output expected from chimp, optionally combined with a output file for the export command. The format is called `naft` and is a bit similar to xml: a tag that describes the type of a certain node as `[tag]` (similar to xml `<tag>`), 0 or more primitive key/value options as `(key0:value0)(key1:value1)...` and support for nesting via `{}` (similar to the xml `</tag>`). Whitespace and newlines in-between these elements do not matter. `\`-based escaping must be used to allow the use of `)` in a key/value. This naft format must be used to represent a filesystem via the tags `[Folder](name:folder name)` and `[File](name:file name)(content:content of file)`. I want a basic CLI that supports encoding a set of folders into a single file and decoding a single file into a set of folders in some base folder. To actually define and drive the chimp end-to-end tests, we should decide to either implement these in Rust itself or in Ruby/Rake. Maybe this has some impact on the design of the naft app and requires the heart of the encoding and decoding to be available directly to the test system.

- [x] The readability of the naft filesystem output is not great: many escaped characters are present. For naft key/value attributes, there is no need to escape `[]{}` or `:` inside the value. And even for `()` we might improve things. Do you think it is a good idea to let the escaping depend on the element type that is being parsed? Also, most things I will encounter have balanced brackets: when `(` is present, `)` is present as well. We could eg support in a naft attribute that if an opening `(` is encountered that is not escaped, the parser accepts chars until the closing `)` is encountered. Only when this nesting level is back at 0 should the parser close the current attribute on a `)`. Something similar can happen for Tags: only the `[]` actually requires escaping and the same nesting principle can be applied for balanced `[]` brackets.
